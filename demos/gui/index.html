默认配置 · 唯一的回落目标
进游戏：鼠标键盘切到规则指定的配置；退出游戏：全部在线设备回到这里。没有逐规则的还原关系，用户不用记任何对应关系。桌面、浏览器、任何未配置的 app 都按未命中处理。
2
开机自启
托盘常驻，不占任务栏。常驻内存目标 ≤ 60MB，空闲 CPU ≤ 0.5%。
匿名遥测：切换失败日志
只上报游戏 ID、设备型号、错误码与固件版本，不含窗口标题、路径、使用时长。失败全量上报，成功只计数——目标是先于售后发现问题。可随时关闭。
诊断信息（售后支持用）
一键复制规则、设备与固件版本、最近日志——社区测试反馈或售后排障时发给我们即可。rules.json 不在界面直接展示。
反作弊安全：纯用户态进程，不注入、不读游戏内存、不做键鼠 hook；只通过标准 HID API 向自家设备配置接口发 Feature Report 0x14。发送路径仅放行 3 条白名单命令，4 条破坏性命令 ID 硬编码拦截。
这张稿子要说明白的事
1
规则页：消费者的首页
页签顺序 = 动手频率。两层模型：游戏 → 每台设备各自的一个板载配置。「添加游戏」弹层只负责选程序；每台设备切到什么只在规则行里配——一个游戏的配置全 app 只有一个入口。查重按 exe 名：已覆盖的标「已添加」，重复添加直接定位到已有规则。
PRD §F1 / F2 · QA-2 · QA-8/9
2
默认配置：唯一的回落目标
退出任何游戏都回到这里，没有例外、没有逐规则的还原关系。用户只需记住这一个概念。
PRD §F2 / §6 · v0.3.2 简化
3
状态页：回答「它在工作吗」
一句话状态 + 流水线 + 设备清单，给消费者看的部分到此为止。它不是用户必须理解的页面，是安心剂。
PRD §F1 / F6
4
容错：设备离线＝静默跳过
BD75 默认离线。切换时它被跳过、记日志、不弹错；插入后若正处于游戏中，自动补切。
PRD §G3 / §7
5
日志：给测试和支持，不给消费者
失败事件匿名遥测自动上报；售后场景用设置页的「复制诊断信息」。三层问题发现链路，先于售后工单。
PRD §F5 / G6
6
模拟器只是演示工具
真实产品里这些按钮不存在——游戏的启动退出、设备的插拔，都由 Windows 事件自动感知。
SetWinEventHook · WM_DEVICECHANGE
信息分层：规则在前（动手），状态在后（安心），日志归测试与支持；
rules.json 不暴露给消费者，诊断走设置页一键复制；
界面只有「产品名 + 板载配置」，槽位号仅是协议层细节；
中英双语（标题栏切换），海外评审与产品 i18n 同步验证。
添加游戏 / 应用
这里只选「哪个程序」。添加后出现在规则列表，每台设备切到哪个板载配置，在规则行里设置——一个游戏的配置全 app 只有这一个入口。同一个程序不会建出两条规则：已被覆盖的标 已添加，重复添加会直接定位到已有规则。来源三层兜底：预置规则包（开箱即用）→ 最近前台历史（玩过即配，自动排除本工具自身）→ 手动选择 exe（冷启动也能加）。
